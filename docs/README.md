# Toolkit documentation and submission materials

The documentation and presentation period is **2–5 December 2026, inclusive**. The internal final deadline is **5 December 2026, 23:59 WAT (UTC+1)**. The official E-Campus deadline takes precedence.

| Date | Activity | Required output |
|---|---|---|
| 2 Dec | Collect accepted artefacts | Version-matched source links, screenshots and QA results |
| 3 Dec | Assemble documentation | Draft abstract, PDF and user guide |
| 4 Dec | Review and rehearse | Corrected PDF, presentation and demonstration script |
| 5 Dec | Finalise submission package | Final files, links, contribution record and submission checklist |

## Operate or present the toolkit

- Follow the user guide for the nine pages, report date, session-local edits and downloads. Use the deployment guide for local operation and rollback.
- Read the project documentation for the design, scoring and limitations. Use the presentation outline and demonstration script for rehearsal.
- Review the [abstract](abstract.md), [project PDF](project_documentation.pdf), [operating model](operating_model.md) and [CLI guide](../src/README.md) alongside the candidate evidence. Existing materials describe the versions identified in those files.

## Assemble the submission

Download the official template from E-Campus. Use it to align the PDF and approximately 200–300-word abstract with the official requirements. Do not invent or substitute an unofficial template.

Include requirements mapping, design, scoring rules, workflow diagrams, version-matched screenshots, test and defect results, limitations, operating instructions, deployment and rollback, accessible repository and live-toolkit links, slides, demo script, verified contributions and the submission checklist. Use screenshots and results from the tested commit only. List only members who actually contributed, record only verified work as complete and retain contribution evidence.

Follow the [documentation workplan and submission checklist](../04-documentation-and-presentation/WORKPLAN.md) and the [QA execution guide](../03-testing-and-quality-assurance/TEST_EXECUTION_GUIDE.md). Every handoff includes the **file path, commit SHA, test result, reviewer, acceptance status and known limitations**.
